## 🧠 Data Link Layer — Last-Minute Memorization

**1. Data Link Layer:** It is **Layer 2 of OSI**. Its main job is to move data safely between **directly connected devices**. It takes data from the Network Layer and organizes it into **frames**. It has two parts: **DLC (Data Link Control)** and **MAC (Medium Access Control)**. 

**2. DLC:** Remember **F-F-E** → **Framing, Flow Control, Error Control**. **Framing** divides data into frames; **Flow Control** prevents a fast sender from overwhelming a slow receiver; **Error Control** handles damaged or lost data. 

**3. MAC:** MAC answers the question: **"Which device can transmit and when?"** It controls access when multiple devices share the same communication channel and uses **MAC addresses** to identify devices on a local network. 

### ⭐ 4. Byte Stuffing vs Bit Stuffing

**Byte stuffing** → add an **extra byte/escape character** when a special byte appears in the data.

**Bit stuffing** → after **five consecutive 1s, insert a 0**. At the receiver, the extra 0 is removed (**unstuffing**). 

🧠 **MEMORIZE:**
**5 ones → add 0**

---

### ⭐ 5. Flow Control vs Error Control

**Flow Control = speed problem** → prevents receiver from being overwhelmed.

**Error Control = damage/loss problem** → handles damaged or lost frames. 

---

### ⭐ 6. Stop-and-Wait

**Stop-and-Wait:**
**Send 1 frame → Wait → ACK → Send next frame.**

It is simple and prevents a fast sender from overwhelming the receiver. 

---

### ⭐⭐⭐ 7. ARQ

**ARQ = Automatic Repeat reQuest.**

If a frame is lost/damaged or its ACK does not arrive, the sender **retransmits** it. The three important ARQ protocols are:

* **Stop-and-Wait ARQ**
* **Go-Back-N ARQ**
* **Selective Repeat ARQ** 

🧠 Think: **ARQ = "Something wrong? Send it again!"**

---

### ⭐⭐⭐ 8. Go-Back-N vs Selective Repeat

This is **very likely worth memorizing**:

**Go-Back-N:** If Frame 3 is lost → resend **3, 4, 5...**

**Selective Repeat:** If Frame 3 is lost → resend **only Frame 3**.

🧠 **GBN = Go back and resend everything after the problem.**
🧠 **SR = Send only the missing one.** 

---

### ⭐ 9. Sliding Window

Instead of:

**Send → Wait → Send → Wait**

the sender can send **multiple frames before waiting for ACKs**.

The number of frames that can be sent at once is called the **Window Size**. The window then moves forward, so it is called **Sliding Window**. 

---

### ⭐ 10. Timer / Timeout

In Stop-and-Wait ARQ, the sender uses a **timer**. If the ACK doesn't arrive before the timer expires, the sender assumes something went wrong and **sends the frame again**. 

---

### ⭐ 11. HDLC

**HDLC = High-Level Data Link Control.**

It is a **bit-oriented data link protocol** that supports reliable communication and ARQ.

Important frame fields:

**Flag | Address | Control | Information/Data | FCS**

* **Flag** → beginning/end of frame
* **Address** → identifies station
* **Control** → sequence numbers, ACK, flow/error control
* **Information** → actual data
* **FCS** → error detection using CRC

Important Flag value: **01111110**. 

---

### ⭐ 12. HDLC Frame Types

Remember **I-S-U**:

**I-frame = Information → carries user data**

**S-frame = Supervisory → ACK, flow/error control**

**U-frame = Unnumbered → control/management** 

---

### ⭐ 13. Piggybacking

**Piggybacking = ACK + data together.**

Instead of sending a separate ACK, the receiver attaches the ACK to a data frame that it is already sending.

🧠 **Piggyback = carry ACK along with data.**

Benefits: fewer frames, less overhead, better bandwidth utilization, higher efficiency. 

---

### ⭐⭐⭐ 14. Error Detection

Two basic errors:

**Single-bit error** → only **one bit changes**.

**Burst error** → **two or more bits** are affected. 

To detect/correct errors, we add **redundant bits**. 

---

### ⭐ 15. VRC / Parity

**VRC = Vertical Redundancy Check**, also called **Parity Check**.

A parity bit is added to data.

**Even parity** → total number of 1s should be **even**.

**Odd parity** → total number of 1s should be **odd**. 

🧠 **Even = even number of 1s.**

---

### ⭐ 16. LRC

**LRC = Longitudinal Redundancy Check.**

It is also called **2-D parity check**. Data is organized into **rows and columns**, and redundant information helps detect errors. 

---

### ⭐⭐⭐ 17. CRC

**CRC = Cyclic Redundancy Check.**

It is an important **error-detection** technique that uses **binary/polynomial division**.

Remember:

**Data → Division → Remainder → CRC**

At the receiver, division is performed again:

**Remainder = 0 → no error detected**

**Remainder ≠ 0 → error detected**

The divisor is called the **Generator / Generator Polynomial**. 

---

### ⭐ 18. Hamming Code

**Hamming Code = Error Correction.**

Easy difference:

**Error detection:** "Something is wrong."

**Error correction:** "Something is wrong, and I can determine/correct it." 

---

# ⭐⭐⭐ 19. ALOHA

ALOHA is a **MAC protocol** for shared broadcast networks.

Two types:

**Pure ALOHA**
→ Transmit **anytime** when you have data.
→ More collisions.
→ Maximum throughput ≈ **18.4%**

**Slotted ALOHA**
→ Time is divided into **slots**.
→ Transmit only at the **beginning of a slot**.
→ Fewer collisions.
→ Maximum throughput ≈ **36.8%** 

🧠 **Pure = Anytime**
🧠 **Slotted = Slot**

And remember:

**18.4% → Pure**
**36.8% → Slotted**

---

### ⭐⭐⭐ 20. CSMA

**CSMA = Carrier Sense Multiple Access.**

Main idea:

> **Listen before you transmit.**

If the channel is busy → **wait**.
If the channel is free → **transmit**. 

---

### ⭐ 21. Types of CSMA

**Nonpersistent:** Channel busy → **wait random time**, then check again.

**1-persistent:** Channel busy → **keep listening**; when free, transmit immediately.

**p-persistent:** When free → transmit with probability **p**, wait with probability **1-p**. 

---

### ⭐⭐⭐ 22. CSMA/CD

**CSMA/CD = Carrier Sense Multiple Access with Collision Detection.**

Remember the process:

**Listen → Transmit → Detect Collision → Stop → Random Wait → Try Again**

That's basically the whole concept.
